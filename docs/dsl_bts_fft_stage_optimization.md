# DSL BTS Collapsed FFT Stage Optimization

Date: 2026-06-05

Commit: `6e1db93 Add collapsed FFT bootstrap stage op`

Branch: `dsl-bts-stage-op-transform`

## Purpose

This document explains the optimization added for the decomposition-based DSL
bootstrap (`dsl-bts`) path.

The goal was to improve the primitive DSL bootstrap without falling back to the
full runtime bootstrap operator. The generated primitive path must still build
the bootstrap from lower-level DSL operators, but it can introduce first-class
IR operators when those operators represent a real reusable bootstrap substage.

The specific optimization was to replace scalar moved rotations in the collapsed
FFT linear transforms with a first-class bootstrap FFT stage operator:

```text
CKKS.bootstrap_fft_stage
```

This operator lowers to:

```text
Eval_bootstrap_fft_stage_ciph(...)
```

The helper executes one collapsed FFT stage through the ANT runtime's stage
native rotate/accumulate implementation instead of forcing the DSL to emit every
moved rotation as an independent scalar rotation.

## Background

The primitive DSL bootstrap is generated by:

- `ace_edsl/examples/bootstrap_full.py`
- `ace_edsl/edsl/core/bootstrap_decomposition.py`

The integrated ResNet validation path is driven by:

- `a_dsl_bts.sh`
- `verify_resnet_first.sh`

The primitive bootstrap decomposes a full CKKS bootstrap into:

1. `CoeffToSlot`
2. full-packed split
3. dual `EvalMod`
4. recombine
5. `SlotToCoeff`
6. post-scale

The transform stages (`CoeffToSlot` and `SlotToCoeff`) are collapsed FFT
diagonal linear transforms. In the runtime bootstrap, these stages are evaluated
with a stage-local schedule: rotations, plaintext multiplies, and accumulation
are organized together. In the previous DSL primitive path, part of this stage
was exposed as individual scalar rotations after a grouped fast-rotation phase.

That mismatch was the main reason the DSL path was slower.

## Profile-Backed Problem Statement

The pre-optimization primitive path was correct, but slower than the `rtlib-bts`
baseline:

| Path | Bootstrap total | Calls | Average |
| --- | ---: | ---: | ---: |
| rtlib baseline | `712.991s` | `21` | `33.952s/call` |
| prior DSL primitive | `980.959s` | `21` | `46.710s/call` |

The non-bootstrap residual was already close to rtlib, so the slowdown was
inside bootstrap:

| Path | Main graph | Bootstrap | Non-bootstrap residual |
| --- | ---: | ---: | ---: |
| rtlib baseline | `899.853s` | `712.991s` | about `186.861s` |
| prior DSL primitive | `1167.688s` | `980.959s` | about `186.729s` |

Runtime counters showed the structural mismatch:

| Counter | rtlib baseline | prior DSL primitive | Delta |
| --- | ---: | ---: | ---: |
| `FHE_ROTATE` count | `1166` | `2048` | `+882` |
| `FHE_ROTATE` time | `72.385s` | `335.575s` | `+263.190s` |

There are `21` bootstrap calls in the one-image ResNet run. The extra `882`
rotations are exactly `42` extra rotations per bootstrap call:

```text
882 / 21 = 42
```

That matched the transform-stage diagnosis: the collapsed FFT moved rotations
were still emitted as scalar rotations in both `CoeffToSlot` and `SlotToCoeff`.

## Implemented Optimization

The final implementation adds a primitive collapsed FFT stage operator instead
of relying on text replacement or coarse bootstrap stage wrappers.

### New CKKS Operator

The new opcode is:

```text
CKKS.bootstrap_fft_stage
```

It carries the metadata needed to execute a single collapsed FFT stage:

- slot count
- stage index
- encoding kind
- whether the stage is a remainder stage
- rotation keys used by the stage

The relevant code paths are:

- `fhe-cmplr/include/fhe/ckks/opcode_def.inc`
- `fhe-cmplr/include/fhe/core/lower_ctx.h`
- `bindings/src/air_builder_bindings.cpp`
- `ace_edsl/edsl/core/air_value.py`
- `ace_edsl/edsl/core/bootstrap_decomposition.py`

### EDSL Generation

The EDSL transform planner now emits one `bootstrap_fft_stage` operation per
collapsed FFT stage when `ACE_BOOTSTRAP_FFT_STAGE_OP=1`.

The stage metadata is derived from the same collapsed FFT stage plan used by
the DSL transform:

```text
_collapsed_fft_stage_plan(...)
_collapsed_fft_stage_rotation_keys(...)
```

This avoids hardcoding ResNet-specific rotation lists. The primitive uses
parameter-derived stage information instead of string replacement over
generated C.

The generated primitive body now contains:

| Generated artifact check | Count |
| --- | ---: |
| `Eval_bootstrap_ciph(` | `0` |
| `Eval_bootstrap_fft_stage_ciph(` | `6` |
| coarse stage wrappers | `0` |
| `dsl_bts_Rotate(` | `0` |
| `Rotate_batch_ciph(` | `0` |
| `Encode_dcmplx_ext(` | `0` |
| raw AIR `CKKS.bootstrap_fft_stage` | `6` |
| raw AIR `CKKS.bootstrap` | `0` |
| raw AIR scalar `CKKS.rotate` | `0` |

### Lowering And Analysis Support

The new opcode is wired through the compiler pipeline:

- CKKS stats classifies it as rotate-like for accounting.
- Scale management models the internal plaintext multiply scale effect.
- Context parameter analysis records the rotation keys from the op metadata.
- CKKS-to-POLY lowering passes the op through as a ciphertext library call.
- IR2C emits `Eval_bootstrap_fft_stage_ciph(...)`.
- The cost model has entries for the new opcode so table lookup remains safe.

Relevant files:

- `fhe-cmplr/ckks/include/ckks_stats.h`
- `fhe-cmplr/ckks/include/scale_manager.h`
- `fhe-cmplr/ckks/src/ckks_cost_model.cxx`
- `fhe-cmplr/include/fhe/core/ctx_param_ana.h`
- `fhe-cmplr/poly/include/ckks2poly.h`
- `fhe-cmplr/poly/src/poly_driver.cxx`
- `fhe-cmplr/include/fhe/ckks/ir2c_handler.h`
- `fhe-cmplr/include/fhe/poly/ir2c_core.h`

### Runtime Helper

The runtime entry point is:

```c
void Eval_bootstrap_fft_stage_ciph(
    CIPHER *res,
    CIPHER ciph,
    uint32_t num_slots,
    uint32_t stage,
    uint32_t encoding,
    bool is_remainder);
```

This helper:

1. ensures bootstrap precomputation is available,
2. selects the correct precomputed FFT diagonal data,
3. executes a single collapsed FFT stage through `Bootstrap_fft_stage(...)`,
4. uses the runtime's stage-native `Rotate_iteration(...)` path.

Relevant files:

- `fhe-cmplr/rtlib/ant/include/ckks/cipher.h`
- `fhe-cmplr/rtlib/ant/ckks/src/cipher.c`
- `fhe-cmplr/rtlib/ant/include/ckks/bootstrap.h`
- `fhe-cmplr/rtlib/ant/ckks/src/bootstrap.c`

One important correctness detail is scale placement. The full runtime
`Coeff_slots_transform(...)` performs rescale inside the transform flow. The
new single-stage helper disables that internal pre-rescale and lets the DSL
emit the explicit per-stage `rescale()` after each stage. This keeps the DSL
scale model consistent with the generated AIR.

Without this fix, the first smoke run produced an invalid scale degree and
decoded zeros. With the explicit per-stage rescale, the first-bootstrap smoke
returned `out_sfdeg=1` and nonzero decoded values.

## Why This Is Not Text Replacement

Earlier experiments used text injection or stage probes to measure parts of the
generated C body. That was useful for diagnosis, but not acceptable as a stable
optimization.

The final implementation does not rewrite generated C text. Instead:

1. Python EDSL emits a first-class CKKS op.
2. The op carries explicit metadata.
3. Compiler passes preserve and lower the op.
4. IR2C emits a normal runtime call.
5. Runtime implements the call as a real bootstrap substage.

This gives the DSL framework a reusable IR-level operator for a complicated FHE
substage while preserving code generation and analysis structure.

## Parameter Generality

The optimization is intended to be parameter-derived, not ResNet-specific.

General aspects:

- stage metadata comes from the collapsed FFT stage plan,
- rotation-key metadata comes from derived stage rotations,
- slot count is passed through operator metadata,
- runtime selects precomputed FFT diagonal data by slot count, encoding, and
  stage,
- the op is represented in AIR instead of generated by text rewrite.

Known risks:

1. The current primitive bootstrap path is still built around the full-packed
   three-stage transform structure used by the active bootstrap parameters.
   Other transform budgets need explicit validation.
2. The EDSL rotation-key derivation and the runtime FFT parameter helper must
   stay aligned. If the BSGS planner changes, the key metadata must be audited.
3. The helper rejects LT bootstrap mode. That is correct for the current
   full-packed path, but it means the op is not yet a generic LT transform
   primitive.
4. Slot metadata must match ciphertext slots. The current path validates the
   ResNet full-packed `32768` slot case; other slot counts should be tested
   before claiming broad coverage.

These are not correctness failures for the validated path, but they define the
next parameter-generalization checks.

## Why We Are Still Slower Than rtlib

After this optimization, `FHE_ROTATE` count and time match rtlib. The remaining
gap is therefore elsewhere.

The main reasons are:

1. `dual_evalmod` is still expanded as generated DSL code.
2. The DSL path still performs more relinearization and polynomial rescale
   work than the integrated rtlib bootstrap.
3. The full rtlib bootstrap can organize EvalMod branches and scale handling
   as one integrated runtime algorithm.
4. The new FFT-stage helper rebuilds per-stage runtime lists around each helper
   call, while full rtlib bootstrap can keep more structure inside one body.

The next performance target should be generated `dual_evalmod`, especially
relinearization and rescale scheduling.

## Summary

The collapsed FFT stage optimization converted the hottest transform mismatch
from scalar generated rotations into a first-class IR/runtime substage.

It achieved:

- full integration correctness,
- no fallback to full runtime bootstrap,
- no generated text replacement,
- `FHE_ROTATE` count parity with rtlib,
- bootstrap average improvement from `46.710s/call` to `36.079s/call`,
- reduction of the rtlib gap from about `267.968s` to about `44.665s` over
  the one-image ResNet run.

The optimization is a real step toward rtlib parity, but it is not final parity.
The next bottleneck is generated EvalMod and its relinearization/rescale
plumbing.
