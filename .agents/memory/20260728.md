# Vector-kernel DSL lowering M4

## Work done

- Added an immutable, AIR-independent planning request and prepared-plan
  package with owned typed payloads, canonical hashes, runtime preparation and
  scalar descriptors, and diagnostics-only provider provenance.
- Extracted the existing C++ Gemm/Conv planning algorithms as the default
  provider for all four baseline/fast variants, with central schema, role,
  type, shape, topology, overflow, key, and preparation validation.
- Added independent provider, implementation, plan-kind, and fallback
  selectors. Missing providers and missing DSL recipes can explicitly fall
  back to C++/native with a diagnostic; invalid requests/results and provider
  failures never fall back.
- Connected validated packages to destination-owned native emission and the
  plan-kind DSL registry. Helper caching is destination-local and keyed by the
  full canonical specialization key plus compatible signature.
- Preserved legacy skip compatibility while validating M4 selectors and plans
  before cloning. Explicit prepared DSL selection still owns the operator, and
  fallback diagnostics are never hidden by a skip.
- Preserved ranked Gemm input types, exact positive-scalar-U32 mask semantics,
  and the authentic sharded Conv `ILD(ARRAY(LDCA, s32-index))` path. Unsupported
  multi-block sharded parallel fast Conv is rejected before provider lookup.
- Kept `New_conv_metakernel_fast` byte-identical to its pre-M4 implementation;
  prepared fast Conv uses a separate emitter. No M5, Python planning provider,
  binding, CKKS, or later milestone work was started.
