## Takeaways

- The current DSL-vs-rtlib performance problem is not in the rest of resnet.
  It is overwhelmingly in bootstrap itself.
- The transform stages dominate the DSL bootstrap cost:
  - `coeff_to_slots + slots_to_coeffs = 38.794s`
  - about `62%` of the call.
- `dual_evalmod` is the second major cost:
  - `23.151s`
  - about `37%` of the call.
- Split, recombine, and post-scale are too small to matter.
- Compared with rtlib per-bootstrap stage means, DSL is slower in all three
  major stages:
  - `CoeffToSlot`: about `1.95x`
  - `ApproxMod`: about `1.81x`
  - `SlotToCoeff`: about `1.81x`
- The helper profile alone is not enough to choose the next target. The stage
  probe is the right level of granularity for the current optimization pass.
- A target-aware raise level is worth keeping, but the benefit is uneven across
  callsites:
  - `level_after_bts = 16` remains near the old cost
  - lower target levels (`14`, `13`, `6`) get large wins
- The integrated runtime Q-chain for this decision comes from the main
  program's `Get_context_params()`, not the bootstrap module's extra context.
- Matching rtlib stage-boundary rescale structure inside the transform gives a
  real additional win and reduces both transform stages plus `dual_evalmod`
  slightly.

## Lessons learned

- For this bootstrap work, a `MAIN_GRAPH` comparison is useful only after also
  checking the bootstrap-call sum or bootstrap stage counters. Otherwise the
  real gap is easy to misattribute.
- The best next optimization order is:
  1. target-level-aware raise
  2. transform path optimization
  3. dual `EvalMod` optimization
  4. ignore split/recombine/post-scale
- `ACE_BOOTSTRAP_STAGE_PROBE=1` is useful as a diagnostic-only tool and should
  stay optional rather than becoming part of the production timing path.
- When specializing bootstrap behavior in the `dsl-bts` integration path, it
  is often cleaner to rewrite the emitted bootstrap C in
  `resnet_bootstrap_utils.py` than to force a deeper compiler change
  immediately, as long as the rewrite preserves the real decomposition path.
- In the current DSL transform path, the safe rescale granularity is per
  collapsed-FFT stage, not per baby-step inner sum.
