## Takeaways

- The user's usual command is container-oriented. `/app` in that command corresponds to the repo root inside the test Docker image.
- `cgo25_ae.py` is not just a compile test:
  - with `-p`, it disables performance mode
  - it still runs the accuracy path by default
  - it expects an OpenMP-enabled installed compiler tree from `-co`
  - it needs CIFAR input data to run the produced executable
- For a native non-DSL bootstrap regression, `fhe-cmplr/test/test_bts_rescale.sh` is the closer backend-only test. It compiles `resnet20_cifar10.onnx` with `-CKKS:mxbl=16:mbc=2:sbm:tsbp` and diffs the resulting bootstrap level log.

## Lessons learned

- When bringing up backend tests first, distinguish three paths early:
  - compile-only regression (`test_bts_rescale.sh`)
  - compile+run AE (`cgo25_ae.py`)
  - EDSL/example-level tests (`ace_edsl/tests/...`)
- On this machine, the blockers are layered:
  1. missing Python dependency (`psutil`)
  2. missing test inputs (ONNX and CIFAR data)
  3. missing installed/build compiler artifacts
  4. host mismatch with Linux/GNU assumptions in the test harness
- The repo does contain generated `.onnx.inc` placeholders under `fhe-cmplr/rtlib/ant/dataset/`, but not the original `.onnx` model files needed by the native compiler test scripts.
- For repeatable backend bring-up here, the cleanest path is to use the Docker image rather than patch the Linux-oriented AE scripts for macOS first.
- The default install prefix build in the container is now viable, so `cgo25_ae.py` can point to `-co /usr/local` as originally intended.
- `make test` at repo root is still wrong for this repo; the working test entrypoint for the configured tree is `ctest` from `/app/build`.
