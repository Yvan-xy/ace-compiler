## Takeaways

- First-call process profiles are still dominated by shared keygen/setup, so
  they are only useful for ruling out bad directions.
- The BSGS retune produced a real but modest integrated win by reducing emitted
  rotate pressure.
- The lazy-rescale rewrite produced the biggest validated gain by cutting
  scale-management overhead.
- A naive alternate rotate lowering is not enough to reduce remaining rotate
  cost; it can easily increase IR/helper pressure and lose badly.
- The resnet integration no longer needs Python text patching for bootstrap
  context/rotate handling.
- The cleaner fix is to preserve rotate metadata in IR (`RNUM`) and let
  `CTX_PARAM_ANA` own rotate-key discovery, then use runtime context merging
  only for multi-module linkage.

## Lessons learned

- Do not optimize helpers shared with the rtlib bootstrap baseline unless there
  is a correctness bug.
- For repeatable DSL profiling, the warm standalone harness is much safer than
  a full resnet integration run.
- When a profile says helper pressure is the problem, changing high-level
  scheduling can help; but changing the helper lowering path itself may backfire
  unless it also reduces the emitted IR/helper count.
- The cleanest bootstrap-link integration is:
  - generated bootstrap body contributes `Get_extra_context_params()`
  - runtime merges that with the program's main `Get_context_params()`
  - compiler/analyzer, not Python text rewriting, owns the rotate-key set
